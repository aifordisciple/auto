# 即席分析经验记忆系统 (Memory Harvester)

## 概述

经验记忆系统是 Autonome 即席分析的原生持久记忆层，让 AI 从成功和失败中吸收经验，避免重复犯错。核心思想借鉴 Hermes 框架的 Long-Term Memory，但完全使用 LangGraph + PostgreSQL 原生实现，零外部框架依赖。

### 解决的问题

即席分析每次生成代码都从零开始（zero-shot），LLM 对同类型分析反复犯相同错误：
- 硬编码文件路径而非使用 argparse/optparse 参数
- 遗漏必要的库导入（如 ggsci、ComplexHeatmap）
- 忘记 CNS 级作图规范（双格式输出、学术配色）
- 参数 schema 与实际代码不一致

用户通常需要经过 2 轮 auto-fix 才能正常运行，经验无法沉淀。

### 设计原则

- **非阻塞异步**：所有提取操作均为 fire-and-forget，失败不影响主流程
- **静默降级**：检索失败时自动回退，不阻塞代码生成
- **零外部依赖**：不依赖 pgvector 扩展（兼容 Docker PostgreSQL:15-alpine），嵌入以 TEXT 列存储，Python 侧计算余弦相似度
- **紧凑注入**：经验文本控制在 ~800 tokens 以内，不影响 LLM 上下文窗口

## 核心服务

### 1. 经验提取器 (`experience_extractor.py`)

#### 触发场景

| 时机 | 文件位置 | 提取内容 |
|------|---------|---------|
| auto-fix 成功 | `adhoc_analysis_node.py` L649 | 原始错误代码 + 修复后代码 + ValidationIssue 列表 |
| 执行成功 | `chat.py` L2219 | 最终工作代码 + 分析策略 + 输出摘要 |
| 执行失败 | `chat.py` L2219 | 错误代码 + 错误输出 + 诊断信息 |

#### 提取流程

```
原始数据（代码 + 问题 + 指令）
    │
    ▼
1. _infer_category() → 从 instruction 关键词推断分类
    │
    ▼
2. _summarize_experience() → LLM 总结：
   - title: 经验标题（20 字以内）
   - summary: 经验摘要（2-3 句话）
   - key_insights: 可操作的教训列表
   - solution_strategy: 解决策略
   - tags: 标签列表
    │
    ▼
3. _generate_embedding() → text-embedding-3-large 生成 1536 维向量
    │
    ▼
4. ExperienceAsset 写入数据库（embedding_text = JSON 数组串）
```

#### 关键实现细节

- LLM 总结使用快速模型（temperature=0.0），通过 `get_fast_llm_config_standalone()` 获取配置
- 嵌入生成复用 `learning_ingestion_service.py` 相同的 OpenAI 客户端模式
- 所有提取操作通过 `asyncio.create_task()` 异步执行，不阻塞 SSE 流
- 提取失败仅记录日志，绝不抛出异常影响主流程

### 2. 经验检索引擎 (`experience_retriever.py`)

#### 检索策略

```
用户 instruction
    │
    ▼
1. _generate_query_embedding() → 生成查询嵌入向量
    │
    ▼
2. 从数据库加载所有有 embedding_text 的经验（按 language 过滤，LIMIT 100）
    │
    ▼
3. Python 侧 numpy 计算余弦相似度：
   score = cosine_sim × 0.5       (语义相似度)
         + usefulness   × 0.3     (有用度评分)
         + log(reuse+1) × 0.1 × 0.2 (重用次数)
   × type_boost (DEBUG_PATTERN = 1.2x)
    │
    ▼
4. 按 score 降序返回 top-3
```

#### 为什么不用 pgvector？

Docker 使用的 `postgres:15-alpine` 镜像不包含 pgvector 扩展。对于百/千级经验规模，Python 侧 numpy 计算余弦相似度性能完全足够（< 50ms）。未来经验规模增长时，可平滑迁移到 pgvector 的 IVFFlat/HNSW 索引。

#### 回退策略

当嵌入不可用时（OPENAI_API_KEY 未配置、API 故障等），自动回退到按有用度评分降序的最近经验检索。

### 3. Prompt 注入格式

```text
## 历史经验教训（从相似分析中自动总结，请特别注意避免以下常见错误）
```

## 反馈闭环

### 有用度动态调整 (`update_experience_feedback`)

```
执行成功 → usefulness = min(1.0, usefulness × 0.7 + 0.3), reuse++ 
执行失败 → usefulness = max(0.0, usefulness × 0.9)
```

使用指数移动平均（EMA）平滑更新，单次波动不会剧烈改变评分。

### 未来扩展

计划中的 Celery 定时任务（复用 `learning_tasks.py` 框架）：
- **每周去重**：合并 cosine_sim > 0.95 的高度相似经验
- **每日衰减**：长期未使用（>30 天）的低分经验自动降权

## 验证方案

### 端到端测试

1. 执行一次 PCA 分析 → 引入硬编码路径错误 → 观察 auto-fix 修复
2. 检查 `experienceasset` 表：确认新增一条 `DEBUG_PATTERN` 记录，`embedding_text` 非空
3. 再次发起相似的 PCA 分析 → 检查 API 日志中"注入 N 条相关经验"
4. 对比两次生成的代码：第二次应避免了第一次的错误

### 性能基准

- 检索延迟：< 50ms（numpy 余弦相似度 + 候选量 < 100）
- 嵌入生成延迟：< 500ms（OpenAI API 调用）
- 经验注入 token 数：< 800（紧凑格式化）
- 提取异步任务：不阻塞主流程（fire-and-forget）

## 设计取舍

| 决策 | 选择 | 原因 |
|------|------|------|
| 嵌入存储 | TEXT 列（JSON 数组）而非 pgvector | Docker PostgreSQL:15-alpine 无 pgvector 扩展 |
| 相似度计算 | Python numpy | 百/千级经验足够，避免数据库扩展依赖 |
| 提取方式 | asyncio.create_task() fire-and-forget | 不阻塞 SSE 流，失败不影响主流程 |
| LLM 总结 | 快速模型（temperature=0.0） | 总结任务简单，快模型足够且成本低 |
| 分类推断 | 关键词规则而非 LLM | 关键词匹配 < 1ms，LLM 调用 > 1s |
| 注入 token 上限 | ~800 tokens | 不影响 LLM 上下文窗口的其他内容 |

### 3. 🔲 反思自循环 (Reflection Loop) — 后续阶段

对应 Hermes 的 **Reflection & Inner Monologue** 思想。

**目标**：在代码生成阶段就拦截 LLM 的"幻觉"和"偷懒"，让用户永远看不到不符合规范的代码。

**当前问题**：`code_validator_node` 目前已存在（`validate_generated_code` + `auto_fix_generated_code`），但它是**被动响应**的——等沙箱报错才触发。反思自循环要在**代码生成阶段**就主动拦截。

**实施步骤**：

```
[skill_forge_node] 生成代码
    │
    ▼
[code_validator_node] (LangGraph 原生节点)
    │
    ├─ AST 静态检查：argparse/optparse 是否声明？
    ├─ 正则检查：是否使用 TASK_OUT_DIR？
    ├─ 模式检查：是否使用 ggsci 配色？（R 代码）
    ├─ 结构检查：是否包含 @ProgramExplanation？
    │
    ├── 通过 ✓ → 流转到下一节点
    │
    └── 不通过 ✗ → Command(goto="skill_forge_node")
                    附带具体批评："你忘了写默认参数，重写！"
                    携带修正指令回到生成节点重写
```

**LangGraph 连线改造**：

```python
# app/agent/graph.py
graph.add_edge("skill_forge_node", "code_validator_node")
graph.add_conditional_edges(
    "code_validator_node",
    _route_after_validation,  # 通过 → UI；不通过 → skill_forge_node
    {"ui_node": "ui_node", "skill_forge_node": "skill_forge_node"},
)
```

**关键文件**：
- 修改 `app/agent/graph.py` — 插入 `code_validator_node` 及条件边
- 增强 `app/services/code_validator.py` — 添加结构化批评生成（用于回退指令）
- 复用 `app/agent/nodes/adhoc_analysis_node.py` — 现有的 ADHOC_SYSTEM_PROMPT 中的规范要求可作为验证规则的来源

```

                    │   反思自循环           │

                           │ 拦住错误代码
                           ▼
用户请求 → 记忆收割机 → LLM 生成代码 → 执行 → 成功/失败

                                               ▼
```

- **记忆收割机**：让 LLM 越写越好（事前预防）
- **反思自循环**：LLM 写错了立刻打回去重写（事中拦截）
- **技能收割机**：好的代码沉淀为团队资产（事后沉淀）

三条线全部落地后，Autonome 将具备完整的自主学习和自我改进能力。"
