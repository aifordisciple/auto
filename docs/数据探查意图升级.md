# 数据探查意图 V2.4 升级文档

> 升级日期: 2026-04-26

---

## 1. 升级概述

### 1.1 背景

数据探查（DATA_PROBE）是 AUTONOME 的核心意图之一，用于识别用户对数据文件的探索需求。V2.4 升级围绕以下三个方向展开：

1. **工具层升级** — 探针工具从11个扩充至14个，新增文件类型检测、MTX矩阵查看、沙箱代码执行
2. **意图识别升级** — L0规则引擎增强编码/分隔符/格式检测，CodeGen规则排除探查动词
3. **架构升级** — 支持DAG条件路由（`DAGCondition`），探针结果可控制后续流程分支

### 1.2 升级范围

| 模块 | 变更类型 | 说明 |
|------|----------|------|
| `app/tools/probe_tools.py` | 新增+修复 | 新增3个工具，修复gzip/gz文件探查，统一错误路径格式 |

## 2. 新工具详解

### 2.1 detect_file_type — 文件类型检测

**功能**: 自动识别文件格式，不依赖扩展名。支持：
- **扩展名检测**: 标准文件后缀映射（csv, tsv, xlsx, h5ad, rds等）
- **魔法字节检测**: BAM/SAM (BAM\1), gzip (1f 8b), HDF5 (8948 4646), Parquet (PAR1), PDF (%PDF)
- **内容模式检测**: VCF (##fileformat=VCF), GTF/GFF (tab分隔9列), FASTA (^>), FASTQ (^@), MTX (%%MatrixMarket), 通用表格 (分隔符统计)

**输出**:
```json
{
  "summary": "✅ 检测结果: CSV 文件 (置信度: 90%)",
  "structured": {
    "primary_type": "CSV",
    "confidence": 0.90,
    "encoding": "utf-8",
    "delimiter": ",",
    "n_columns": 5,
    "details": {...}
  }
}
```

### 2.2 inspect_mtx — MTX矩阵文件查看

**功能**: 解析 MatrixMarket 格式的稀疏矩阵文件。支持：
- 读取头部信息（格式、存储类型、对称性）
- 提取维度数据（行数/列数/非零元素数）
- 计算稀疏度（非零占比 %）
- 透明解压 gzip 压缩的 .mtx.gz 文件

**输出**:
```json
{
  "summary": "MatrixMarket 矩阵: 2700×32738, 2286884 个非零元素, 稀疏度: 2.59%",
  "structured": {
    "format": "coordinate",
    "field": "real",
    "symmetry": "general",
    "n_rows": 2700,
    "n_cols": 32738,
    "n_entries": 2286884,
    "sparsity_pct": 2.59
  }
}
```

### 2.3 sandbox_probe — 沙箱代码执行

**功能**: 在 Docker 沙箱中执行自定义 Python 代码进行深度探查。使用 `run_container_simple` 隔离执行。
- 60秒超时保护
- 工作区路径安全约束
- 延迟导入避免循环依赖（`bio_tools` ↔ `probe_tools`）

**输出**:
```json
{
  "summary": "沙箱执行成功: 输出 1024 字节",
  "structured": {
    "success": true,
    "stdout": "完整标准输出...",
    "stderr": "",
    "execution_time_ms": 1250
  }
}
```

## 3. 架构升级

### 3.1 DAG 条件路由

新增 `DAGCondition` 模型，支持基于探针结果的 DAG 分支决策：

```python
class DAGCondition(BaseModel):
    field: str              # 探查报告中的字段名（如 "n_rows", "overall_na_ratio"）
    operator: str           # 比较操作符: gt, lt, gte, lte, eq, neq
    value: Any              # 比较阈值
    on_true: str = "stop"   # 条件为真时路由目标
    on_false: str = "continue"  # 条件为假时路由目标
    source_task_id: str     # 数据来源任务ID
```

**路由函数**: `evaluate_condition_and_route(state)` 位于 `graph.py`，具备完整的降级链：
- 无condition → 继续执行
- probe_report解析失败 → 继续执行
- 无probe_report → END（安全停止）
- 缺少指定字段 → END
- 操作符类型错误 → END

### 3.2 结构化探针报告

`data_probe_node` 升级为收集结构化探查报告：

```python
probe_reports: Dict[str, Any] = {}  # {tool_name: structured_fields}

# 单工具调用
probe_report = {"tool_name": "detect_na", "fields": {"overall_na_ratio": 0.02}}

# 多工具链式调用
probe_report = {
    "tool_name": "detect_na",
    "fields": {...},
    "all_tools": {"detect_na": {...}, "peek_tabular_data": {...}}
}
```

### 3.3 路径安全强化

`PATH_PARAM_MAP` 新增3个工具的安全映射：
- `detect_file_type`: file_path
- `inspect_mtx`: file_path
- `sandbox_probe`: workspace_path

所有文件路径统一经过 `_apply_path_safety` 校正（相对路径拼接、越界路径截断）。

## 4. L0 规则升级

### 4.1 编码/分隔符/格式检测（无需 active_file）

V2.4 关键改进：乱码/打不开的文件不会是 `active_file`，但仍需路由到 DATA_PROBE。

`FILE_EXPLORATION_KEYWORDS` 新增关键词：
```
检测编码 | 检测分隔符 | 检测格式 | 检测文件格式 |
探测编码 | 探测分隔符 | 探测格式 | 探测文件格式 |
编码检测 | 分隔符检测 | 格式检测 | 文件编码 | 编码格式 |
乱码 | 打不开 | 文件格式 | 分隔符 | 什么编码 | 什么分隔符 |
MTX | 矩阵文件 | Matrix Market | 文件类型 | 什么类型 | 判断类型
```

### 4.2 CodeGen 规则探查动词排除

`CodeGenPatternRule`（优先级7）新增 `PROBE_VERB_EXCLUSION`：

```python
PROBE_VERB_EXCLUSION = re.compile(
    r'(扫描|检查.*文件|看看.*文件|查看.*文件|预览|探测|配对)'
)
```

效果：
- "跑流程前，扫描FASTQ文件夹" → 不拦截为 SKILL_FORGE，放行至 ProbePatternRule
- "检查一下目录结构再跑流程" → 同上
- "跑分析流程" → 正确路由到 SKILL_FORGE

### 4.3 CodeGenPatternRule 置信度修正

`CodeGenPatternRule` 置信度从 0.80 提升至 0.85，达到 `L0_CONFIDENCE_THRESHOLD` (0.85)确定性拦截标准。原因：CODEGEN_PATTERN 同时要求执行动词（跑/运行/执行/做/进行/run/execute）+ 目标（分析/流程/pipeline/代码/脚本），组合高度特定，误判率低。

## 5. Bug 修复

### 5.1 gzip/gz 文件无法探查

**症状**: `peek_tabular_data` 和 `inspect_fastq` 对 .gz 压缩文件返回乱码或无法解析。

**原因**: 工具直接以文本方式打开 gzip 压缩文件，读取到的是二进制压缩内容。

**修复**:
- `peek_tabular_data`: 检测 .gz 扩展名，使用 `gzip.open(f, 'rt')` 透明解压
- `inspect_mtx`: 支持 gzip 压缩的 MatrixMarket 文件（.mtx.gz）
- 同时在文件开头进行 magic bytes 检测（1f 8b）作为兜底

### 5.2 错误路径未使用双模 JSON

**症状**: `peek_tabular_data` 和 `scan_workspace` 的错误路径（文件不存在、非文件、目录不存在等）返回纯文本字符串，导致上层解析失败。

**修复**: 所有错误路径统一使用 `_make_probe_result("错误描述", {"error": "error_code"})` 返回双模 JSON。

### 5.3 CodeGenPatternRule 置信度过低

**症状**: "跑分析流程" 等明确的代码执行请求无法被 L0 确定性拦截，放行至 L1 导致延迟增加。

**修复**: 置信度从 0.80 提升至 0.85，达到确定性拦截阈值。
