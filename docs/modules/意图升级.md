### ⚙️ 底层架构流转全景推演 (The LangGraph Workflow)

为了实现这个极致丝滑的用户体验，我们需要利用 LangGraph 的**多节点复合编排**以及前端的 **Vercel AI SDK 工具调用（Tool Calling）**。

当用户输入：“*请用这个 `expr_matrix.tsv` 数据绘制一个热图*”时，系统的流转如下：

#### Step 1: L1 路由拆解 (The Brain)
L1 解构器识别出这是一个“即席分析”，生成包含两个隐藏节点的 DAG：
`[Task A: 快速代码锻造]` -> `[Task B: 渲染即席分析卡片并挂起等待执行]`

#### Step 2: 后台静默锻造 (Skill Forge - Silent Mode)
* `skill_forge_node` 接收任务，发现这是即席模式。
* 它生成一段使用 `ComplexHeatmap` 的 R 代码，包含 `--input`, `--cluster_cols`, `--color_palette` 等参数。
* **关键动作**：它不仅输出代码，还同步输出了一个 JSON Schema（例如：调色板有 `npg`, `jco` 可选，默认 `npg`）。

#### Step 3: 前端 Generative UI 渲染 (The Strategy Card)
系统暂停图谱流转，向前端发送一个特定的 ToolCall（如 `render_adhoc_analysis_card`）。前端立刻渲染出你描述的那个“超级卡片”，包含四个区域：
1. **分析策略区**：“将使用 ComplexHeatmap 对矩阵进行 Z-score 标准化并绘制聚类热图...”
2. **可视化参数区（表单）**：输入文件已自动锁定为 `expr_matrix.tsv`。聚类方法、调色板等参数以“下拉框/滑块”展示，并预填了生信默认值。
3. **代码预览与沉淀区**：折叠显示生成的 R 代码。旁边有一个高亮的按钮 `[⭐ 固化为平台技能]`。
4. **行动区**：一个醒目的 `[🚀 执行分析]` 按钮。

#### Step 4: 用户交互与分支流转
* **分支 A（用户修改代码/参数）**：用户在表单里把配色改成了 `Lancet`，或者在对话框说“把聚类方法改成 Ward.D2”。UI 卡片局部刷新。
* **分支 B（固化技能）**：用户点击 `[⭐ 固化为平台技能]`，触发底层的 `collaboration_node`，将代码和 Schema 写入数据库，以后系统就多了一个“绘制热图”的固定技能。
* **分支 C（点击执行）**：用户点击 `[🚀 执行分析]`，前端将最终的参数 JSON 发回后端。

#### Step 5: 真实算力执行 (Explicit Exec)
* 状态机恢复流转，将拿到的最终参数直接喂给 `explicit_skill_node`。
* Celery 调度 Docker 沙箱，挂载数据，运行脚本。
* 运行结束后，沙箱销毁。前端卡片翻转或在下方追加一个**结果预览区**（展示 300DPI 热图的 PNG 预览，以及 `.pdf` 和 `.tsv` 结果文件树的下载链接）。

  }},

    task = state["dag"].nodes[idx]

```tsx
  }, {} as Record<string, any>);

  const [formData, setFormData] = useState(initialFormState);
  const [isExecuting, setIsExecuting] = useState(false);
  const [showCode, setShowCode] = useState(false);

  // 处理参数变化
  const handleParamChange = (key: string, value: any) => {
    setFormData(prev => ({ ...prev, [key]: value }));
  };

  // 核心：点击执行，将参数通过 Vercel AI SDK 送回后端
  const handleExecute = async () => {
    setIsExecuting(true);
    // 合并用户填写的参数和底层文件映射
    const finalPayload = {
      parameters: formData,
      inputs: input_mapping,
      code_snapshot: code // 将代码快照一并传回，防止后端丢失上下文
    };
    
    // 调用 Vercel AI SDK 的回调，这会触发后端的流式响应继续进行
    addToolResult({
      toolCallId,
      result: { action: 'execute', payload: finalPayload }
    });
  };

  // 固化技能到资产库 (此处的 API 调用视你的基础库而定)
  const handleSaveSkill = () => {
    // 这里可以调用你的内部 API，比如 POST /api/skills
    console.log("Saving skill with schema:", parameter_schema, "and code:", code);
    alert("技能已固化到团队库！");
  };

  return (
    <div className="border border-indigo-200 rounded-xl bg-white shadow-sm overflow-hidden my-4">
      {/* 头部：策略说明 */}
      <div className="bg-indigo-50/50 p-4 border-b border-indigo-100">
        <h3 className="font-bold text-indigo-900 flex items-center gap-2">
          <span>⚡ 即席分析就绪</span>
        </h3>
        <p className="text-gray-600 text-sm mt-2">{strategy}</p>
      </div>

      {/* 中部：可视化参数面板 (动态表单) */}
      <div className="p-4 grid grid-cols-1 sm:grid-cols-2 gap-4">
        {Object.entries(parameter_schema?.properties || {}).map(([key, field]: [string, any]) => (
          <div key={key} className="flex flex-col gap-1.5">
            <label className="text-sm font-medium text-gray-700">{field.title || key}</label>
            {field.enum ? (
              <select 
                className="flex h-9 w-full rounded-md border border-input bg-transparent px-3 py-1 text-sm shadow-sm"
                value={formData[key]}
                onChange={(e) => handleParamChange(key, e.target.value)}
              >
                {field.enum.map((opt: string) => (
                  <option key={opt} value={opt}>{opt}</option>
                ))}
              </select>
            ) : field.type === 'boolean' ? (
               <input 
                 type="checkbox" 
                 checked={formData[key]}
                 onChange={(e) => handleParamChange(key, e.target.checked)}
               />
            ) : (
              <Input 
                type={field.type === 'number' ? 'number' : 'text'}
                value={formData[key]}
                onChange={(e) => handleParamChange(key, field.type === 'number' ? Number(e.target.value) : e.target.value)}
              />
            )}
          </div>
        ))}
      </div>

      {/* 代码预览区 */}
      <div className="px-4">
        <button 
          onClick={() => setShowCode(!showCode)}
          className="text-xs text-indigo-600 hover:underline mb-2"
        >
          {showCode ? '隐藏底层代码' : '查看/编辑底层代码'}
        </button>
        {showCode && (
          <pre className="text-xs bg-gray-900 text-gray-100 p-3 rounded-md overflow-x-auto mb-4">
            <code>{code}</code>
          </pre>
        )}
      </div>

      {/* 底部：操作按钮 */}
      <div className="p-4 bg-gray-50 flex justify-between items-center border-t">
        <Button variant="outline" size="sm" onClick={handleSaveSkill} className="text-gray-600">
          ⭐ 固化为团队技能
        </Button>
        <Button 
          size="sm" 
          onClick={handleExecute} 
          disabled={isExecuting}
          className="bg-indigo-600 hover:bg-indigo-700 text-white"
        >
          {isExecuting ? '沙箱启动中...' : '🚀 执行分析'}
        </Button>
      </div>
    </div>
  );
};
```

### 第三步：Vercel AI SDK 消息流拦截

最后，我们需要在前端的对话主渲染循环中，拦截后端发来的 `render_adhoc_card` 工具调用请求，并渲染刚刚写好的组件。

打开你的消息列表组件（例如 `autonome-studio/src/components/chat/VirtualizedMessageList.tsx` 或 `ChatStage.tsx`）：

```tsx
import { ToolInvocation } from 'ai';
import { AdhocAnalysisCard } from './components/AdhocAnalysisCard';

// 假设这是你渲染单条消息的组件或循环
export function ChatMessageList({ messages, addToolResult }: any) {
  return (
    <div className="flex flex-col gap-4 p-4">
      {messages.map(m => (
        <div key={m.id} className="message-container">
          
          {/* 1. 渲染普通文本 */}
          {m.content && <div className="markdown-body">{m.content}</div>}
          
          {/* 2. 拦截并渲染 Tool Invocations (Generative UI) */}
          {m.toolInvocations?.map((toolInvocation: ToolInvocation) => {
            const toolCallId = toolInvocation.toolCallId;
            
            // 处理即席分析卡片
            if (toolInvocation.toolName === 'render_adhoc_card') {
              
              // 状态一：等待用户输入（挂起状态）
              if (!('result' in toolInvocation)) {
                return (
                  <AdhocAnalysisCard 
                    key={toolCallId}
                    toolCallId={toolCallId}
                    args={toolInvocation.args}
                    addToolResult={addToolResult} 
                  />
                );
              }
              
              // 状态二：用户已经点击了“执行”，后端返回了最终结果
              if ('result' in toolInvocation) {
                const executionResult = toolInvocation.result;
                return (
                  <div key={toolCallId} className="my-2 p-4 bg-green-50 border border-green-200 rounded-xl">
                    <h4 className="text-green-800 font-bold mb-2">✅ 分析执行完成</h4>
                    <p className="text-sm text-gray-600 mb-3">参数已确认，沙箱执行成功。</p>
                    {/* 渲染后端返回的结果文件树 */}
                    {executionResult?.fileTree && (
                       <FileTree files={executionResult.fileTree} />
                    )}
                  </div>
                );
              }
            }
            
            // 处理其他工具 (如 L2 的参数反问 probing)
            return null; 
          })}
          
        </div>
      ))}
    </div>
  );
}
```

### 总结与流转闭环

这三步完成后，你的应用就具备了以下能力：
1. 后端一旦识别到“帮我用这个数据画图”，就会通过大模型生成 JSON（策略、Schema、代码）。
2. 后端不直接执行，而是包装成一个 `ToolCall(name="render_adhoc_card")` 发给前端。
3. 前端的 `useChat` 接收到这个 ToolCall，渲染出 `AdhocAnalysisCard`，用户可以看到参数并修改。
4. 用户点击 **执行**，前端调用 `addToolResult`。
5. 后端 LangGraph 收到 `addToolResult`，挂起的状态机重新激活，顺着 DAG 把代码和最新的参数交给底层的 Celery Worker 执行。
6. 执行完毕后，将输出文件的树状结构作为 `result` 发回前端渲染成功卡片。
