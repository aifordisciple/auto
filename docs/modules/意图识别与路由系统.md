# Autonome Studio 意图识别与路由功能全景蓝图 (V2.0 终极版)

## 一、 核心设计理念：AI-Native 生信集成开发环境
本系统基于 **“Router(意图分发) - Worker(专业执行) - Validator(规范校验)”** 的多智能体架构，旨在解决生信分析中长尾需求复杂、参数静默失败、运行环境隔离以及科研输出不规范的核心痛点。

---

## 二、 核心意图分类字典 (Atomic Intent Taxonomy)
系统采用 MECE（相互独立、完全穷尽）原则，将用户输入解构为以下 12 种原子意图。L1 解构器负责将自然语言转化为由这些原子意图按时序或逻辑分支组合而成的有向无环图（DAG）。

### 第一组：计算、编排与工程 (Compute & Engineering)
**1. 工作流编排意图 (`INTENT_WORKFLOW_ORCHESTRATE`)**
* **触发场景**：用户需要串联多个独立步骤，或处理多组学宏观分析链路。
* **行为规范**：拦截手工硬编码行为，强制激活对话式 AI 辅助生成向导。通过多轮对话确认通道（Channels）和进程（Processes），自动生成并拼装可执行的 Nextflow 脚本及 `main.nf`。仅负责“调度”和“串联”，不负责单一脚本的具体实现。

**2. 代码锻造意图 (`INTENT_SKILL_FORGE`)**
* **触发场景**：从零编写、调试或重构具体的单一数据分析脚本（Python/R/Perl 等）。
* **行为规范**：调度沙箱与代码智能体。**硬性约束**：生成的代码必须自带完整的参数解析系统并设定默认值；在对现有代码进行迭代和重构时，系统必须开启“非破坏性更新”模式，绝对不可丢失或删减历史版本中原有的详细程序说明和行级注释。

**3. 显式技能执行意图 (`INTENT_EXPLICIT_EXEC`)**
* **触发场景**：调用已封装好的标准技能（如“运行 FastQC”），且明确需要投入算力资源的动作。
* **行为规范**：触发 L2 参数提取器。如果关键参数齐备，则直接将任务及其上下文挂载到 Docker 暖池沙箱中独立运行并监听退出码。

**4. 版本与历史控制意图 (`INTENT_VERSION_CONTROL`)**
* **触发场景**：管理分析上下文的变迁（如“回滚到 10 分钟前的代码”或“对比这两个分析版本的结果差异”）。
* **行为规范**：对接底层 Git 或状态快照树，恢复代码区与工作区状态。

### 第二组：视觉感知与数据探究 (Perception & Discovery)
**5. 视觉感知与图形管护意图 (`INTENT_VISUAL_PERCEPTION_AND_TWEAK`)**
* **触发场景**：所有以“视觉与图形”为核心的输入与控制需求，包含：
    * **看图释义 (Image Interpretation)**：上传分析结果图（如 UMAP、复杂热图），要求解释生物学意义或异常点。
    * **看图写码 (Visual Reverse Engineering)**：提供目标参考图截图，要求逆向解析视觉元素（排版、映射关系、图例风格），并生成复刻代码。
    * **视图微调 (State & Parameter Tweak)**：仅对已有结果进行轻量级绘图参数重载（如“调整 P 值阈值为 0.01”、“更改配色为专业方案”）。
* **行为规范**：
    * 严禁调度全量计算型沙箱，仅调度轻量级绘图环境或更新前端视图状态。
    * 必须调用多模态视觉模型提取坐标映射逻辑（Aesthetics）和调色板体系。
    * **最高优先级约束**：强制同时生成发表级别（SCI-level）的高分辨率 PDF 与 PNG 双版本图像；同步抽取并输出该图形对应的、以 Tab 分割的 `.tsv` 格式底层坐标与阈值数据文件。

**6. 数据探究意图 (`INTENT_DATA_PROBE`)**
* **触发场景**：对未知结构化/半结构化数据进行初步了解（如“看看这个矩阵的分布”、“检查有没有 NA 值”）。
* **行为规范**：极短时间内计算全局统计量，通常作为 DAG 中条件分支判定（If/Else）的前置意图。

**7. 文献与图谱解析意图 (`INTENT_LITERATURE_MINING`)**
* **触发场景**：针对上传的 PDF 文献进行逆向工程。
* **行为规范**：调用多模态大模型分离图文，基于 pgvector 进行向量检索，提取特定算法的软件版本和参数逻辑，为“代码锻造”提供事实依据。

### 第三组：系统运维与协作 (Operations & Collaboration)
**8. 系统与资产调度意图 (`INTENT_SYSTEM_ASSET_OPS`)**
* **触发场景**：涉及计算资源分配、文件系统管护及计费查询（如“切换到本地大内存节点”、“查询本月计算资源账单”）。
* **行为规范**：对接 Kubernetes/Docker 编排接口、文件系统网关及 Stripe 支付 API。

**9. 团队协作与权限意图 (`INTENT_COLLABORATION`)**
* **触发场景**：跨用户资产共享（如“把这组热图共享给合作 PI 并设置只读权限”）。
* **行为规范**：调度 IAM 模块更新资产 ACL 权限，并生成跨会话的共享链接或通知。

**10. 错误诊断与自愈意图 (`INTENT_DIAGNOSTIC_RECOVERY`)**
* **触发场景**：底层任务执行非正常退出（Exit Code != 0），或前端抛出依赖异常。
* **行为规范**：自动提取 Stderr，进行根因分析，生成补丁并流转给代码锻造节点闭环自愈。

### 第四组：通用兜底 (General Support)
**11. 通用问答与长尾意图 (`INTENT_GENERAL_CHAT`)**
* **触发场景**：生信概念解释、起草学术信函等跨领域自然语言输入。
* **行为规范**：使用标准 Chat 模型轻量级流式回复，不触发文件系统或计算沙箱。

**12. 系统宏与精准缓存意图 (`INTENT_SYSTEM_MACRO`)**
* **触发场景**：系统级快捷指令（`/status`, `/clear`）或命中本地向量数据库中极高置信度的高频模板。
* **行为规范**：L0 层直接拦截，绕过大模型解析，实现毫秒级响应。

## 三、 核心路由引擎 (Router Engine) 架构

路由引擎从单向线性流转升级为**带有中断/反问机制的异步状态机 (State Machine)**。

### L0: 规则拦截与毫秒级缓存层
* **旁路机制**：通过 Redis + pgvector 检索近期完全匹配的查询，若相似度 > 0.95 且参数完整，直接透传执行指令。
* **短文本流转**：对“确定”、“继续”等确认指令，直接透传给当前挂起或活跃的 Worker 上下文。

### L1: 意图解构器 (DAG Decomposer) - 核心大脑
* **多意图任务拆解**：将复合自然语言拆解为带有依赖关系的执行图谱。
* **指代消解 (Coreference Resolution)**：结合短期记忆快照，将代词（“用它跑”、“过滤这些”）映射到三栏布局左侧（资产区）的具体 FileID。
* **状态同步**：路由前自动捕获当前工作区、UI 状态和沙箱状态快照。

### L2: 参数探测与主动拦截 (Active Probing)
* **系统参数对齐**：为 L1 生成的子任务提取参数，并与底层脚本的 `schema.yaml` 默认参数比对。
* **硬性中断**：当关键参数（如 scRNA-seq 的 `species`）缺失时，L2 会挂起当前路由。
* **生成式交互**：在中栏（对话区）渲染 Generative UI 表单，用户通过下拉/滑杆补全参数后，状态机恢复流转，避免反复无效对话。

## 四、 扩展的工作节点层 (Worker Agents)
针对 L1 拆解的任务，系统部署 8 大专业智能体进行隔离处理。

1. **Orchestrator Agent**：负责 Pipeline 级别的意图串联与 Nextflow 代码生成。
2. **Skill Forge Agent**：执行原子脚本的编写与代码重构，内置强制注释保留审计器。
3. **Explicit Skill Agent**：负责 Docker 暖池沙箱的生命周期管理及结果提取。
4. **UI/State Agent**：不重启后端，直接重载前端可视化参数，生成 SCI 图表及制图数据。
5. **System/Asset Agent**：对接系统底层进行资源与账单运维。
6. **Data Probe Agent**：快速预览矩阵元数据与分布。
7. **Literature Agent**：对接 PDF 多模态处理，提供方法学溯源。
8. **Diagnostic Agent**：读取异常日志并输出自愈策略。

这份 V2.0 终极版蓝图非常完备，逻辑严密，彻底实现了从“单轮对话”向“Agentic 工作流编排”的范式跃迁。

### 阶段二：重构 L1 解构器与 L2 探针 (Router Engine)
**目标**：赋予大模型任务拆解能力，并实现参数缺失时的硬中断机制。

1. **L1 意图解构器升级 (DAG Decomposer)**

2. **L2 参数探测与主动拦截 (Active Probing)**
   * **文件**：`autonome-backend/app/agent/router/l2_extractor.py`

     * **不要抛出普通的 Exception**，而是返回一个特定的状态对象（例如 `ProbingRequiredState`），包含缺失的参数列表和默认值建议。

### 阶段三：LangGraph 状态机重塑 (StateGraph Orchestration)
**目标**：让底层的调度图支持多任务的串行/并行调度，以及 L2 的挂起状态。

1. **改造全局 Agent State**
   * **文件**：`autonome-backend/app/agent/graph.py`
   * **操作**：修改 `AgentState`，增加 `dag: TaskDAG`，`current_task_id: str`，以及 `pending_probing_request: dict` 字段。
2. **调整连线逻辑 (Edges)**
   * **操作**：
     * 路由判断不再是单一走向。执行完一个 Worker Node 后，检查 `dag` 中是否还有未完成的子任务，如果有，回传给调度中心进行下一个任务的派发。
     * 当 L2 Router 返回 `ProbingRequiredState` 时，中断 LangGraph 的自动执行，将状态返回给前端（通过 Vercel AI SDK 抛出一个 Tool Call）。

### 阶段四：补全与强化 Worker Agents (Backend Nodes)
**目标**：实现蓝图中的 8 大专业智能体，并严格落实 SCI 输出约束和代码合规。

1. **新增核心代理节点**
   * 在 `autonome-backend/app/agent/nodes/` 目录下新增：
     * `orchestrator_node.py` (生成 Nextflow 流程)
     * `ui_state_node.py` (视觉微调与 SCI 级输出)
     * `system_asset_node.py` (K8s/Docker 资源调度与 Stripe 计费)

3. **强化 UI/State Node 数据对称性**
   * **操作**：在节点逻辑中硬编码后处理流程：只要生成了 `.pdf` 或 `.png`，强制要求底层的绘图脚本同步产出绘制该图使用的坐标、阈值或分类 `.tsv` 数据，并将其持久化到资产库。

### 阶段五：前端生成式 UI 与交互适配 (Frontend Vercel AI SDK)
**目标**：响应后端的 Active Probing，实现流畅的表单交互与视图更新。

1. **处理主动反问 (Active Probing UI)**
   * **文件**：`autonome-studio/src/hooks/useChat.ts` 或相关组件
   * **操作**：拦截后端发出的 `request_missing_parameters` 类型的 Tool Call。

2. **多模态文件上传与视觉感知**
   * **文件**：`autonome-studio/src/components/chat/ChatInputBox.tsx`
   * **操作**：确保图片/文献上传功能与后端的 Vision Model API（如 GPT-4o 或 Claude 3.5 Sonnet）联通，支持 L1 解构器触发 `INTENT_VISUAL_PERCEPTION_AND_TWEAK` 意图。

### 步骤 1：更新意图枚举与 DAG 数据模型

请打开（或创建）后端的 `autonome-backend/app/agent/router/schemas.py` 文件，用以下代码替换现有的基础数据结构。这里我们引入了蓝图中的 12 个意图和完整的 `TaskDAG` 模型。

```python
from enum import Enum
from typing import List, Dict, Any, Optional
from pydantic import BaseModel, Field

class IntentType(str, Enum):
    """Autonome Studio V2.0 核心原子意图字典"""
    # 1. 计算与编排 (Compute & Engineering)
    WORKFLOW_ORCHESTRATE = "INTENT_WORKFLOW_ORCHESTRATE"
    SKILL_FORGE = "INTENT_SKILL_FORGE"
    EXPLICIT_EXEC = "INTENT_EXPLICIT_EXEC"
    VERSION_CONTROL = "INTENT_VERSION_CONTROL"
    
    # 2. 视觉与探究 (Perception & Discovery)
    VISUAL_PERCEPTION_AND_TWEAK = "INTENT_VISUAL_PERCEPTION_AND_TWEAK"
    DATA_PROBE = "INTENT_DATA_PROBE"
    LITERATURE_MINING = "INTENT_LITERATURE_MINING"
    
    # 3. 运维与协作 (Operations & Collaboration)
    SYSTEM_ASSET_OPS = "INTENT_SYSTEM_ASSET_OPS"
    COLLABORATION = "INTENT_COLLABORATION"
    DIAGNOSTIC_RECOVERY = "INTENT_DIAGNOSTIC_RECOVERY"
    
    # 4. 通用兜底 (General Support)
    GENERAL_CHAT = "INTENT_GENERAL_CHAT"
    SYSTEM_MACRO = "INTENT_SYSTEM_MACRO"

class TaskNode(BaseModel):
    """DAG 中的单一执行节点"""
    task_id: str = Field(..., description="子任务的唯一标识符，如 'task_1'")
    intent: IntentType = Field(..., description="解析出的原子意图类型")
    raw_instruction: str = Field(..., description="该子任务对应的具体自然语言指令")
    dependencies: List[str] = Field(default_factory=list, description="依赖的前置 task_id 列表")
    resolved_assets: List[str] = Field(default_factory=list, description="指代消解后的具体 FileID 或 DB_Hash")
    parameters: Dict[str, Any] = Field(default_factory=dict, description="初步提取的关键参数（若有）")

class TaskDAG(BaseModel):
    """由多个 TaskNode 组成的有向无环图"""
    nodes: List[TaskNode] = Field(..., description="构成本次执行图谱的子任务节点列表")
    is_conditional: bool = Field(default=False, description="图中是否包含 If/Else 条件分支探针逻辑")
```
