异常处理与边界情况

每种失败都有明确的恢复路径，用户不会陷入死胡同

Agent 生成失败

LLM 返回不可执行代码 / 超时 / 格式异常 → 自动重试 1 次，仍失败则展示原始输出 + 错误说明，让用户决定：手动修复 / 重新描述需求 / 简化需求

静态检查失败

安全问题 / 语法错误 → Agent 自动修复（最多 3 轮），每轮将错误信息喂回 LLM。3 轮后仍未通过 → 展示问题列表，用户手动修

自动测试失败

Docker 执行报错 / 输出不符合预期 → 展示：错误日志 + AI 分析的可能原因 + 建议修复方案。用户可选择：让 Agent 修复 / 忽略直接发布 / 手动修

用户中断

任何阶段点击「暂停」→ Agent 保存当前状态到 ForgeSession → 用户可以：继续 / 在 Forge 中手动编辑 / 重新开始。已生成的部分不丢失

SSE 连接中断

网络断开 / 刷新页面 → 自动恢复。重连后从 ForgeSession 拉取最新状态，继续渲染已完成的阶段。未完成的阶段重新触发或让用户手动继续

意图模糊

用户输入「帮我做一个分析技能」→ Agent 不瞎猜，而是回问关键问题：什么类型的数据？期望什么输出？用什么工具？最多追问 3 轮

重复 skill_id

生成的 skill_id 冲突 → Agent 自动追加后缀 + 提示用户可手动改名

阶段预计超时超时策略
